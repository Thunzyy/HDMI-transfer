  <name>Task 1: Implement SequentialProtocol class</name>
  <files>src/hdmi_exfil/protocols/sequential.py</files>
  <action>
    Create `src/hdmi_exfil/protocols/sequential.py` with class `SequentialProtocol(EncodingProtocol)`:

    1. `__init__(self)`: No arguments needed. Load constants from `hdmi_exfil.config`.

    2. `name` property: Return `"sequential"`.

    3. `bytes_per_frame` property: Return `BYTES_PER_FRAME` from config.

    4. `encode_frame(self, data, frame_index, total_frames, *, frame_type=FRAME_TYPE_DATA)`:
       - EXACT same logic as sender.py encode_frame (lines 59-104):
         - Build pre-CRC header with struct.pack(SEQ_HEADER_FMT, SEQ_MAGIC, frame_type, frame_index, total_frames, len(data))
         - Compute CRC32 over header + data
         - Concatenate header + CRC + data
         - Convert to bits with np.unpackbits
         - Pad to BLOCKS_PER_FRAME * 3 bits
         - Reshape to (ROWS, COLS, 3), map 0->0 1->255
         - cv2.resize to (WIDTH, HEIGHT) with INTER_NEAREST
       - Do NOT include the sys.stdout.write progress line (that's UI, belongs in CLI)
       - Return numpy array (HEIGHT, WIDTH, 3) uint8

    5. `decode_frame(self, sampled_grid)`:
       - Logic from receiver.py decode_frame_full (lines 97-134) -- the 5-field version
       - Returns FrameResult(data=payload, frame_type=frame_type, frame_index=frame_index, total_frames=total_frames, is_valid=True) on success
       - Returns FrameResult(data=None, frame_type=None, frame_index=None, total_frames=None, is_valid=False) on any failure (bad magic, CRC mismatch, bad data_len)
       - Threshold: flat_pixels > 128

    6. Additional class methods (NOT part of ABC, specific to sequential):
       - `encode_start_frame(self, filename, file_data, total_data_frames)`: Uses metadata.build_start_metadata + self.encode_frame with frame_type=FRAME_TYPE_START
       - `encode_end_frame(self, total_data_frames)`: Encodes b'\x00' with frame_type=FRAME_TYPE_END

    7. Add a `decode_frame_legacy(self, sampled_grid)` method that returns the old 4-tuple (frame_index, total_frames, data, data_len) for backward compatibility. This calls decode_frame internally and unpacks.

    8. Add `TransferState` class (Enum FSM extracted from receiver.py lines 137-158):
       - States: START_PENDING, RECEIVING, COMPLETE
       - This is the sequential-specific transfer lifecycle state machine used by cli/receive.py to track progress through START -> DATA... -> END frame sequence.
       - Import: `from enum import Enum, auto`

    Imports: numpy, cv2, struct, zlib, enum from stdlib/deps. From hdmi_exfil: config constants, protocols.base (ABC + FrameResult), file_handling.metadata (build_start_metadata).

    IMPORTANT: Do NOT modify sender.py or receiver.py. This is a parallel implementation.
  </action>
