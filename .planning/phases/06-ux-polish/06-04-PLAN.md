**Create `src/hdmi_exfil/display/test_patterns.py`:**

Implement two functions:

1. `generate_checkerboard(profile: ResolutionProfile) -> np.ndarray`:
   - Returns a (height, width, 3) uint8 frame with alternating black/white blocks
   - Each block is `block_size x block_size` pixels
   - Pattern: block at (row, col) is white if `(row + col) % 2 == 0`, black otherwise
   - Uses ONLY black (0,0,0) and white (255,255,255) to survive chroma subsampling
   - This pattern encodes a known bit sequence: alternating 0b111 and 0b000 in 3bpp

2. `generate_known_payload(profile: ResolutionProfile) -> tuple[np.ndarray, bytes]`:
   - Generates a frame encoding the byte 0xAA repeated to fill the frame
   - 0xAA = 10101010 binary, which creates an alternating bit pattern in the 3bpp encoding
   - Returns both the encoded frame image and the expected decoded bytes
   - Uses SequentialProtocol(profile=profile).encode_frame() to create the frame
   - This gives a more realistic test than pure checkerboard (includes header, CRC)

3. `compute_snr(captured: np.ndarray, expected: np.ndarray, block_size: int) -> float`:
   - Computes signal-to-noise ratio from captured vs expected frames
   - Sample block centres from both frames
   - Split into "should be white" and "should be black" populations based on expected values
   - Signal = mean(white_population) - mean(black_population)
   - Noise = (std(white_population) + std(black_population)) / 2
   - Return `20 * log10(signal / noise)` in dB
   - Return 60.0 if noise < 1e-6 (perfect capture)

4. `compute_alignment(captured: np.ndarray, expected: np.ndarray) -> tuple[int, int]`:
   - Compute pixel alignment offset between captured and expected frames
   - Convert both to grayscale
   - Use `cv2.matchTemplate` with `cv2.TM_CCOEFF_NORMED` on a central crop
   - Return (offset_x, offset_y) as integer pixel offsets

**Create `src/hdmi_exfil/cli/calibrate.py`:**

Implement `main()` entry point for `hdmi-calibrate` CLI:

1. Parse args: `source` (camera index or file), `--profile`, `--output-dir`
2. Resolve profile from --profile flag (default: speed)
3. Mode selection:
   - `hdmi-calibrate send` -- display calibration pattern on screen (uses renderer)
   - `hdmi-calibrate recv <source>` -- capture and analyze calibration pattern
   - `hdmi-calibrate loopback <source>` -- both: display pattern, capture, analyze (same machine)

For `send` subcommand:
- Generate checkerboard pattern using `generate_checkerboard(profile)`
- Display using renderer (pygame or cv2)
- Print "Displaying calibration pattern. Press any key to exit."
- Wait for keypress, then exit

For `recv` subcommand:
- Open capture source
- Capture N frames (e.g., 10) and average them (reduce noise)
- Generate expected checkerboard pattern
- Call `compute_alignment()` to get offset
- Call `compute_snr()` to get signal quality
- Print results:
  ```
  Calibration Results:
    Alignment offset: (dx, dy) pixels
    SNR: XX.X dB
    Signal quality: EXCELLENT/GOOD/FAIR/POOR
    Recommended: [block size advice]
  ```
- Quality thresholds: >30dB EXCELLENT, >20dB GOOD, >10dB FAIR, <10dB POOR

For `loopback` subcommand:
- Combine send + recv: display pattern, wait 2s, capture, analyze

**Create `src/hdmi_exfil/cli/benchmark.py`:**

1. Define `BenchmarkResult` dataclass:
   ```python
   @dataclass
   class BenchmarkResult:
       profile: str
       mode: str  # "sequential" or "fountain"
       frames_per_sec: float
       bytes_per_sec: float
       overhead_pct: float  # fountain only, 0.0 for sequential
       error_rate: float
       duration_sec: float
       total_frames: int
       total_bytes: int

       def to_json(self) -> str:
           return json.dumps(asdict(self), indent=2)
   ```

2. Implement `run_benchmark(profile, mode, payload_size_kb, duration_sec) -> BenchmarkResult`:
   - Generate random test payload of `payload_size_kb * 1024` bytes
   - Create protocol instance: `get_protocol(mode, profile=profile)`
   - For **sequential** mode:
     - Compute total frames needed
     - Time a tight loop encoding all frames (no display)
     - Time decoding all frames (encode -> sample_frame -> decode roundtrip in memory)
     - Measure frames/sec and bytes/sec
     - Count decode errors (CRC mismatches) for error_rate
   - For **fountain** mode:
     - Compute K chunks and generate droplets in a tight loop
     - Encode, sample (resize to block grid and back), decode
     - Measure how many droplets needed to recover all K chunks
     - overhead_pct = ((droplets_needed - K) / K) * 100
     - Measure frames/sec and bytes/sec

3. Implement `main()` entry point for `hdmi-bench`:
   - Args: `--profile` (default: speed), `--mode` (default: fountain), `--size` (payload KB, default: 100), `--duration` (seconds, default: 10), `--json` (output as JSON, default: true)
   - Run benchmark
   - Output BenchmarkResult as JSON to stdout
   - If not --json, print human-readable summary
