       ```python
       )
       ```

    2. Add imports at top (alongside existing ones):
       ```python
       from hdmi_exfil.display.renderer import PygameRenderer
       from hdmi_exfil.protocols.xor_ops import warmup as warmup_numba
       ```

    3. Update `main()` to select renderer based on `--renderer` flag:
       ```python
       # Choose renderer
       if args.renderer == "pygame":
           renderer_cls = PygameRenderer
           renderer_kwargs = {"width": WIDTH, "height": HEIGHT, "x_offset": x_offset, "y_offset": y_offset}
       ```

    4. Add Numba warmup during calibration screen:
       ```python
       # Warm up Numba JIT before data transfer

       ```
       Place this after the calibration frame is shown (during "Press any key to start" wait), so compilation happens while the user hasn't started yet.

    5. Update `_send_fountain()` to use numpy arrays for XOR instead of pure Python:
       - Change the XOR loop from:
         ```python
         payload = bytearray(FOUNTAIN_PAYLOAD_SIZE)
         for idx in indices:
             chunk = chunks[idx]
             for b in range(FOUNTAIN_PAYLOAD_SIZE):
                 payload[b] ^= chunk[b]
         ```
         To:
         ```python
         from hdmi_exfil.protocols.xor_ops import xor_into
         payload = np.zeros(FOUNTAIN_PAYLOAD_SIZE, dtype=np.uint8)
         for idx in indices:
             xor_into(payload, chunks[idx])
         ```
       - Change the chunks list to store numpy arrays:
         ```python
         chunks: list[np.ndarray] = []
         for i in range(K):
             start = i * FOUNTAIN_PAYLOAD_SIZE
             end = min(start + FOUNTAIN_PAYLOAD_SIZE, len(wrapped))
             chunk = np.zeros(FOUNTAIN_PAYLOAD_SIZE, dtype=np.uint8)
             chunk[:end - start] = np.frombuffer(wrapped[start:end], dtype=np.uint8)
             chunks.append(chunk)
         ```
       - When calling `protocol.encode_frame`, convert payload back to bytes:
         `protocol.encode_frame(payload.tobytes(), frame_count, K, seed=seed)`

    6. Update the FOUNTAIN_PAYLOAD_SIZE import to use the new 3bpp constant (which is already updated in fountain.py from plan 04-01). The import `from hdmi_exfil.protocols.fountain import PAYLOAD_SIZE as FOUNTAIN_PAYLOAD_SIZE` stays the same -- the constant's value changed from 4038 to 12138 inside fountain.py.

    7. For PygameRenderer, the pause/end screen helpers use cv2.putText which won't work with pygame. Two options:
       - If renderer is pygame: use simple colored frames (solid blue for pause, solid green for done) without text overlay. The text output goes to terminal (print statements already exist).
       - If renderer is cv2: keep existing behavior.
       Simplest approach: make the pause/end screen functions check the renderer type and use appropriate drawing method. For pygame, fill the surface with a solid color. The user sees status in the terminal output anyway.

    IMPORTANT: The `_show_pause_screen` and `_show_end_screen` helpers use cv2.putText and renderer.show(). For PygameRenderer, these need adaptation. The cleanest approach: create pause/end frames as plain numpy arrays (solid color, no text) and pass them to renderer.show(). This works for both renderers since both accept (H,W,3) numpy arrays. Remove cv2.putText calls and rely on terminal output for status messages.

  <name>Task 2: Wire ThreadedCapture and FPS reporting into receive.py</name>
  <files>src/hdmi_exfil/cli/receive.py</files>
  <action>
    Modify `src/hdmi_exfil/cli/receive.py`:

    1. Add imports:
       ```python
       from hdmi_exfil.capture.threaded import ThreadedCapture, FPSReporter
       ```

    2. Add `--threaded` CLI flag:
       ```python
       parser.add_argument(
           "--threaded",
           action="store_true",
           default=True,
           help="Use threaded capture with ring buffer (default: enabled)",
       )
       parser.add_argument(
           "--no-threaded",
           action="store_false",
           dest="threaded",
           help="Disable threaded capture (use blocking reads)",
       )
       parser.add_argument(
           "--buffer-size",
           type=int,
           default=16,
           help="Ring buffer size for threaded capture (default: 16 frames)",
       )
       ```

    3. Update `main()` to wrap CaptureSource in ThreadedCapture when --threaded:
       ```python
       with cap:
           if args.threaded:
               tcap = ThreadedCapture(cap, buffer_size=args.buffer_size)
               with tcap:
                   _run_receiver(tcap, args)
           else:
               _run_receiver(cap, args)
       ```
       Extract the mode dispatch logic into a helper `_run_receiver(source, args)` that takes any source with .read(). This avoids duplicating the mode selection code.

    4. Add FPS reporting to the receive loops. In both `_receive_sequential` and `_receive_fountain`:
       - Create `fps_reporter = FPSReporter(report_interval_s=2.0)` at loop start
       - After each successful `cap.read()`, call `fps = fps_reporter.tick()`
       - When fps is not None, include it in the progress output:
         ```python
         if fps is not None:
             capture_fps_str = f" | Capture: {fps:.1f} FPS"
         ```
       - Append capture FPS to existing progress line

    5. Update the function signatures: `_receive_sequential`, `_receive_fountain`, and `_receive_auto` should accept `cap` as a generic source (not specifically CaptureSource). The duck typing already works since both CaptureSource and ThreadedCapture implement `.read() -> (bool, frame)`.

    6. At the end of a transfer (in _finalize_sequential and _finalize_fountain), print total capture stats:
       ```python
       if hasattr(cap, 'capture_fps_reporter'):
           reporter = cap.capture_fps_reporter
           print(f"Capture: {reporter.total_frames} frames captured")
       ```

    IMPORTANT: The ThreadedCapture.read() is non-blocking and returns (False, None) when buffer is empty. The receive loops already handle `ret == False` with `continue` or `break`. However, with threaded capture, the loop may spin fast when buffer is empty. Add a tiny `time.sleep(0.001)` after `ret == False` to avoid CPU spinning:
    ```python
    ret, frame = cap.read()
    if not ret:
        time.sleep(0.001)  # avoid CPU spin when buffer is empty
        continue
    ```
    This only adds 1ms latency when no frame is available, which is negligible.
