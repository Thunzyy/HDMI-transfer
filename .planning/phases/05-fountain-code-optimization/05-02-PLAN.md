<objective>
Add Gaussian elimination fallback decoder to FountainDecoder for when belief propagation (peeling) stalls.

Purpose: FOUNT-02 requires GE fallback for small K where BP commonly stalls. BP requires degree-1 droplets to make progress; when the "ripple" dies (no degree-1 droplets available), decoding halts even though enough information exists in the unresolved droplets to solve the system. GE operates in GF(2) and can recover all remaining chunks from any sufficient set of linearly independent equations.

Output: `gaussian_elimination_fallback()` method on FountainDecoder, automatic trigger when BP stalls, tests proving recovery for small K.
</objective>

<feature>
  <name>Gaussian Elimination Fallback Decoder</name>
  <files>src/hdmi_exfil/protocols/fountain.py, tests/test_fountain_ge.py</files>
  <behavior>
    GF(2) Gaussian elimination on unresolved fountain droplets.

    Cases:
    - Decoder with K=5, fed N droplets where BP stalled at 3/5 chunks → GE recovers remaining 2 chunks → is_complete() True
    - Decoder with K=10, BP stalls at 7/10 → GE with 3+ unresolved droplets covering the 3 unknowns → recovers all
    - Decoder where BP already completed → GE not triggered (no overhead)
    - Decoder with insufficient equations (fewer droplets than unknowns) → GE returns False, decoder continues receiving

    Algorithm:
    1. Collect unresolved droplets: [(indices_set, data_array), ...] where len(indices) > 0
    2. Identify unknown chunk indices: all indices referenced by unresolved droplets that aren't in self.chunks
    3. If n_equations < n_unknowns → return False (underdetermined)
    4. Build binary matrix M (n_equations x n_unknowns) where M[i][j] = 1 if droplet i references unknown j
    5. Build data matrix D (n_equations x payload_size) as numpy uint8
    6. Row-reduce M using GF(2) Gaussian elimination (XOR row operations, applied to both M and D)
    7. Back-substitute to recover each unknown chunk's data
    8. Call self.resolve_chunk() for each recovered chunk (triggers BP propagation of any remaining)
    9. Return True if any new chunks resolved

    CRITICAL: All matrix operations are in GF(2) — addition is XOR, multiplication is AND.
    CRITICAL: Row operations on D must use xor_into or numpy XOR (not regular addition).
    CRITICAL: Pivot selection: find first row with 1 in current column, swap to diagonal position.
  </behavior>
  <implementation>
    1. Add gaussian_elimination_fallback() method to FountainDecoder:
       - Collect unresolved: [(d[0], d[1]) for d in self.droplets if len(d[0]) > 0]
       - Map unknown indices to 0..N-1 column positions
       - Build M as numpy uint8 matrix (n_eqs x n_unknowns)
       - Build D as numpy uint8 matrix (n_eqs x payload_size)
       - Forward elimination: for each column, find pivot row, swap, XOR all rows below
       - Back substitution: for each column from last to first, XOR all rows above
       - Extract solved chunks from D diagonal rows where M[i][i] == 1
       - Call self.resolve_chunk(actual_chunk_idx, solved_data) for each

    2. Add try_gaussian_elimination() method as the trigger point:
       - Called from add_droplet() after normal peeling when decoder is not complete
       - Only attempt if: not is_complete() AND n_unresolved_droplets >= n_unknown_chunks
       - Call gaussian_elimination_fallback()
       - This is a "try" — if it fails (underdetermined), just continue receiving

    3. Modify add_droplet() to call try_gaussian_elimination() at the end:
       - After the existing peeling logic
       - Only if decoder is not yet complete
       - Lightweight check: len(self.chunks) < self.K

    4. Tests in test_fountain_ge.py:
       - test_ge_recovers_when_bp_stalls: Construct a scenario where BP cannot make progress but GE can
       - test_ge_small_k: Round-trip with K=5 using minimal droplets
       - test_ge_not_triggered_when_bp_sufficient: K=1 case, verify GE never called
       - test_ge_with_insufficient_equations: Feed fewer droplets than unknowns, verify graceful failure
       - test_ge_round_trip_various_k: Parametrized test for K=3,5,10,20 — all recover correctly
  </implementation>
</feature>
