    - Replace `print("SUCCESS/FAILURE")` pattern with proper `assert` statements: `assert decoded_data[:file_size] == file_data` at the end.
    - Use `tmp_path` fixture (or `tempfile`) instead of writing `test_data.bin` to cwd. Accept `tmp_path` as parameter, write temp file there, clean up automatically.
    - Keep the file generation and encode/decode loop structure, but make it a proper pytest test.

    CREATE test_sequential.py (TEST-02) with these tests:

    1. `test_single_frame_roundtrip_full` -- Fill exactly BYTES_PER_FRAME bytes with known data (e.g., `b'\x42' * BYTES_PER_FRAME`), encode with `encode_frame(data, 0, 1)`, pass through `sample_frame()`, decode with `decode_frame()`, assert `idx == 0`, `total == 1`, `decoded == data`.

    2. `test_single_frame_roundtrip_partial` -- Use data smaller than BYTES_PER_FRAME (e.g., 100 bytes of `b'\xAB'`). Encode, sample, decode. Assert `length == 100` and `decoded[:100] == original_data`.

    3. `test_multi_frame_roundtrip` -- Create data that spans 3 frames (e.g., `os.urandom(BYTES_PER_FRAME * 3 - 500)`). Split into chunks, encode each with correct frame_index and total_frames, sample each, decode each, reassemble, assert byte-for-byte match with original.

    4. `test_frame_index_preserved` -- Encode 5 frames with indices 0-4, decode each, verify each decoded index matches.

    5. `test_total_frames_preserved` -- Encode with total_frames=42, decode, verify total_frames == 42 in output.

    6. `test_empty_data_handling` -- Encode empty bytes `b''`, sample, decode. Verify decode returns `(None, None, None, None)` since data_len would be 0 and the sanity check in decode_frame rejects `data_len == 0`.

    7. `test_all_zeros_data` -- BYTES_PER_FRAME of `b'\x00'`. Encode, decode, verify match.

    8. `test_all_ones_data` -- BYTES_PER_FRAME of `b'\xFF'`. Encode, decode, verify match.

    Import from: `sender.encode_frame`, `receiver.sample_frame`, `receiver.decode_frame`, `common.BYTES_PER_FRAME`.

    Note: `encode_frame` writes progress to stdout. Accept the noise -- do NOT modify production code. Optionally use `capsys` fixture if output is distracting.

    Note: `sender.py` imports `ctypes` and `ctypes.wintypes` at module level. On Linux, `ctypes` exists but `wintypes` will fail. If import fails, wrap the import in test_sequential.py with a try/except or patch. The research says "happen to work on Linux but could break." If they break, import only `encode_frame` function by extracting it or by mocking the module-level imports. Test this during implementation -- if `from sender import encode_frame` works on Linux, proceed normally. If it fails with ImportError on wintypes, use `importlib` to load just the function or monkeypatch `ctypes.wintypes` before import.
